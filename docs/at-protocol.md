# AT 프로토콜 — ESP32-S3 ↔ MM32

> MM32 펌웨어(`x3-switch`)가 USART2로 제공하는 유일한 외부 인터페이스.
> 역할 분담과 배선은 [architecture.md](architecture.md), 핀과 전기적 동작은
> [hardware.md](hardware.md)를 본다.

## 1. 전송 파라미터

| 항목 | 값 |
|---|---|
| 포트 | MM32 USART2 — PA2 (TX) / PA3 (RX) |
| 속도 | **115200 bps**, 8N1, 흐름제어 없음 |
| 실측 오차 | PCLK1 24 MHz → `BRR=13`, `FRA=0` → 115384 bps (+0.16 %) |
| 문자셋 | ASCII |

## 2. 프레이밍 규칙

- **수신**(ESP32 → MM32): 줄 끝은 `\r\n` · `\n` · `\r` 모두 허용. 빈 줄은 무시한다.
- **송신**(MM32 → ESP32): 모든 줄은 항상 `\r\n`으로 끝난다.
- 명령 이름과 인자의 영문자는 **대소문자를 구분하지 않는다** (`at+led=3,w` = `AT+LED=3,W`).
- 줄 앞뒤의 공백은 버린다. 인자 사이의 공백은 허용하지 않는다.
- 한 줄은 **최대 64 바이트**. 넘으면 그 줄을 버리고 `ERROR` 한 번을 보낸다.
- 명령은 한 줄에 하나. 응답을 받기 전에 다음 명령을 보내지 않는 것을 권장한다.

### 응답 형태

| 형태 | 의미 |
|---|---|
| `OK` | 성공. 값을 돌려주는 명령은 `+이름:값` 줄을 **먼저** 보내고 마지막에 `OK` |
| `ERROR` | 실패. 모르는 명령, 인자 개수·범위 오류, 문법 오류를 구분하지 않는다 |
| `+이름:값` | 요청에 대한 값, 또는 비요청 통보 |

> 오류를 한 가지로 묶은 것은 의도적이다. 채널 3~4개짜리 장치에서 ESP32가 오류 번호에
> 따라 다르게 행동할 일이 없다. 진단은 MM32의 RTT 로그에 사유를 남겨 처리한다.

## 3. 명령

### 3.1 요약

| 명령 | 응답 | 설명 |
|---|---|---|
| `AT` | `OK` | 생존 확인 |
| `AT+RELAY=<ch>,<0\|1>` | `OK` | 릴레이 제어. ch = 1~4 |
| `AT+RELAY?` | `+RELAY:<l1>,<l2>,<l3>,<l4>` `OK` | |
| `AT+LED=<ch>,<W\|O\|T>` | `OK` | 버튼 LED. ch = 1~4 |
| `AT+LED?` | `+LED:<c1>,<c2>,<c3>,<c4>` `OK` | |
| `AT+LEDIVL=<ch>,<ms>` | `OK` | `T` 상태의 점멸 주기. ch = 1~4 |
| `AT+LEDIVL?` | `+LEDIVL:<i1>,<i2>,<i3>,<i4>` `OK` | |
| `AT+LEDEN=<0\|1>` | `OK` | LED 레일 전체 |
| `AT+LEDEN?` | `+LEDEN:<0\|1>` `OK` | |
| `AT+LEDBRI=<0~100>` | `OK` | 밝기 % (PWM) |
| `AT+LEDBRI?` | `+LEDBRI:<0~100>` `OK` | |
| `AT+KEY?` | `+KEYS:<k1>,<k2>,<k3>,<k4>` `OK` | 현재 눌림 상태 |
| `AT+STATUS?` | 아래 참조 | 위 상태를 한 번에 |
| `AT+VER?` | `+VER:x3-switch,<버전>` `OK` | |
| `AT+RST` | `OK` 후 리셋 | 소프트 리셋 |

### 3.2 릴레이 — `AT+RELAY`

```
AT+RELAY=1,1        → OK          L1 접점 ON
AT+RELAY=3,0        → OK          L3 접점 OFF
AT+RELAY?           → +RELAY:1,0,0,0
                      OK
```

- `ch` = 1~4 → 전면 드라이버 L1(PA8) · L2(PB8) · L3(PA10) · L4(PA11)
- 값 `1` = 코일 활성 = 접점 ON (MCU 핀 HIGH)
- **전면 PCB에는 4채널 드라이버가 모두 실장되어 있다.** 후면 릴레이만 방마다
  다르다 — 큰방은 L1~L3, 나머지는 L1~L2.
- **릴레이가 없는 채널에 명령해도 `OK`를 반환한다.** 드라이버는 구동되지만
  코일이 없어 아무 일도 일어나지 않는다. MM32는 실장 여부를 알 수 없으므로
  어느 채널이 실제 전등인지는 ESP32가 관리한다.
- **L4는 후면에 릴레이도 단자대 용도도 없다.** 그래도 드라이버 Q8이 실장되어
  있어 채널로 열어 두었다 — 나중에 쓸 일이 생기면 후면에 릴레이만 추가하면 된다.

### 3.3 버튼 LED — `AT+LED`

```
AT+LED=3,W          → OK          K3 흰색
AT+LED=2,O          → OK          K2 주황
AT+LED=1,T          → OK          K1 흰색↔주황 점멸
AT+LED?             → +LED:T,O,W,O
                      OK
```

| 값 | 의미 | 핀 동작 |
|---|---|---|
| `W` | 흰색 | 출력 HIGH → NPN ON |
| `O` | 주황 | 출력 LOW → MCU가 주황 캐소드를 sink |
| `T` | 점멸 | `W`와 `O`를 그 채널의 `LEDIVL` 주기로 번갈아 |

- `AT+LED?`는 **설정값**을 돌려준다. `T` 채널의 그 순간 색이 아니라 `T`로 보고한다.
- 채널별 소등은 **하드웨어적으로 불가능하다.** 핀을 하이임피던스로 두면
  레일 → 주황 LED → 120 Ω → 4.7 kΩ → NPN 베이스로 DC 경로가 살아 있어
  흰색이 켜진다 (2026-09-22 실측 확인). 소등은 `AT+LEDEN=0`뿐이다.

### 3.4 점멸 주기 — `AT+LEDIVL`

```
AT+LEDIVL=1,1000    → OK          K1 주기 1000 ms (기본값)
AT+LEDIVL=2,250     → OK          K2만 빠르게
AT+LEDIVL?          → +LEDIVL:1000,250,1000,1000
                      OK
```

| 항목 | 값 |
|---|---|
| 단위 | **밀리초(ms)** |
| 기본값 | **1000** (채널 4개 모두) |
| 범위 | **100 ~ 60000**. 벗어나면 `ERROR`이며 기존 값을 유지한다 |
| 의미 | 한 가지 색이 유지되는 시간. 한 주기(흰→주황→흰)는 `2 × LEDIVL` |

- 주기는 **채널마다 따로** 가지며 위상도 채널마다 독립이다. 서로 다른 속도로
  깜빡이는 표시를 만들 수 있다 — 예를 들어 난방 동작 중인 K2는 1000 ms,
  WiFi가 끊긴 K1은 200 ms.
- 채널을 `T`로 바꾸면 **흰색부터 시작**하고 그 시점부터 자기 주기를 센다.
  주기가 같아도 `T`로 바꾼 시점이 다르면 위상이 어긋난다. 여러 채널을 맞춰
  깜빡이게 하려면 `AT+LED=<ch>,T`를 연달아 보내면 된다 (115200 bps에서 명령
  하나가 ~1 ms라 육안으로는 동시에 시작한 것과 같다).
- `T`가 아닌 채널에도 주기를 미리 넣어둘 수 있다. 그 채널이 `T`가 될 때 적용된다.
- 주기를 바꾸면 **다음 전환부터** 적용된다. 현재 색이 이미 새 주기보다 오래
  유지되었다면 곧바로 전환된다.
- 하한을 100 ms로 둔 것은 그보다 빠르면 깜빡임이 아니라 밝기가 떨어진 것처럼
  보여 표시로서 의미가 없기 때문이다.
- `LEDEN=0`이어도 점멸은 내부적으로 계속 돌아간다. 레일을 다시 켜면 이어서 보인다.

### 3.5 LED 전체 전원 — `AT+LEDEN`

```
AT+LEDEN=0          → OK          전체 소등 (QP1 OFF)
AT+LEDEN?           → +LEDEN:0
                      OK
```

`LED_EN`(PB9)은 QP1 P-MOSFET 게이트다. 펌웨어가 극성을 감추므로 **`1` = 점등**이다
(핀 레벨은 LOW). 채널별 `W`/`O`/`T` 설정은 레일이 꺼져 있어도 보존된다.

**`LEDEN`과 [`LEDBRI`](#36-led-밝기--atledbri)는 같은 핀을 제어하지만, 상태는
펌웨어 변수가 갖고 레지스터는 그 결과일 뿐이다.**

| 명령 | 펌웨어 상태 | 하드웨어 반영 |
|---|---|---|
| `AT+LEDEN` | `en` (bool) | `CCR1 = en ? duty(bri) : 0` |
| `AT+LEDBRI` | `bri` (0~100) | 위와 같은 식. `en=0`이면 값만 저장하고 출력은 그대로 꺼둔다 |

`CCR1 = 0`이면 PWM1 + active-low 조합에서 출력이 계속 비활성 = **HIGH로 능동 구동**되어
QP1이 확실히 닫힌다.

> **`BDTR.MOE`로 끄지 않는 이유**: `MOE=0`일 때의 핀 상태는 `BDTR.OSSI`에 달려 있고,
> `OSSI=0`이면 출력이 Hi-Z로 풀린다. P-MOSFET 게이트가 뜨면 QP1이 어정쩡한 상태로
> 남을 수 있다. `CCR1`만 쓰면 핀이 항상 구동되므로 그 경우의 수가 없다.

**밝기 값은 펌웨어 변수로 보존된다.** `LEDEN=0`이어도 `bri` 값은 지워지지 않고,
`LEDEN=1`을 주면 **꺼지기 직전의 밝기로 그대로 복귀한다.** ESP32는 이전 밝기를
기억했다가 다시 보낼 필요가 없다.

`LEDEN=0` 상태에서도:

| 동작 | 결과 |
|---|---|
| `AT+LEDBRI=30` | `OK`. 값만 저장되고 화면은 계속 꺼져 있다. 다음 `LEDEN=1`에서 30 %로 켜진다 |
| `AT+LEDBRI?` | 저장된 값을 그대로 돌려준다 (`+LEDBRI:30`). 0을 돌려주지 않는다 |
| `AT+LED=<ch>,<W\|O\|T>` | `OK`. 채널 색과 점멸도 내부적으로 계속 유지·진행된다 |
| `AT+STATUS?` | 저장된 값들을 보고한다. 꺼져 있다는 사실은 `+LEDEN:0`으로만 나타난다 |

```
AT+LEDBRI=60        → OK
AT+LEDEN=0          → OK          소등 (밝기 60은 유지)
AT+LEDBRI?          → +LEDBRI:60                 ← 꺼져 있어도 값은 살아 있다
                      OK
AT+LEDEN=1          → OK          다시 60 %로 점등
```

> **실측 확인 (2026-09-22)**: 위 순서를 펌웨어로 돌리며 `CCR1`과 상태 변수를 함께
> 읽어 검증했다. `en=0`에서 `CCR1=0`이 되고 `bri=60`은 변수에 남았으며,
> 소등 중 `bri=10`으로 바꾼 값이 다음 점등에서 `CCR1=100`(10 %)으로 적용됐고,
> 다시 켤 때 `CCR1=600`(60 %)으로 정확히 복귀했다.

화면 ON/OFF는 `LEDEN`으로, 밝기 조절은 `LEDBRI`로 쓰는 것이 의도된 사용법이다.

### 3.6 LED 밝기 — `AT+LEDBRI`

```
AT+LEDBRI=100       → OK          최대 (기본값)
AT+LEDBRI=20        → OK          야간용으로 어둡게
AT+LEDBRI?          → +LEDBRI:20
                      OK
```

| 항목 | 값 |
|---|---|
| 단위 | **퍼센트(%)**, 정수 |
| 기본값 | **100** |
| 범위 | 0 ~ 100. 벗어나면 `ERROR`이며 기존 값을 유지한다 |
| 구현 | `LED_EN`(PB9) = **TIM17_CH1 (AF2)** PWM, **1 kHz 고정** |

`LED_EN` 핀이 타이머 채널 위에 있어 레일 자체를 PWM으로 게이팅한다.
흰색과 주황이 같은 비율로 어두워지므로 색 균형은 변하지 않는다.

- **실제 출력 = `LEDEN` AND `LEDBRI`** 이다 (§3.5의 레지스터 표 참조).
  `LEDEN=0`이면 밝기와 무관하게 꺼지고, 다시 `LEDEN=1`을 주면 설정해 둔 밝기로
  돌아온다. `LEDBRI=0`도 결과는 소등이지만, 화면 ON/OFF에는 `LEDEN`을 쓴다.
- 듀티는 **선형**이다. 사람 눈에는 50 %가 절반보다 밝게 보이므로, 감마 보정이
  필요하면 ESP32가 미리 굽혀서 보낸다. MM32는 받은 값을 그대로 듀티로 쓴다.
- PWM 주파수 1 kHz는 깜빡임이 보이지 않으면서 QP1 게이트 RC(AO3401A Ciss ≈ 730 pF,
  RD9 직렬)에 비해 충분히 느린 값이다.
- 극성은 타이머가 처리한다 (`TIM_OCPolarity_Low`). `LED_EN`은 LOW가 점등이다.

> **실측 확인 (2026-09-22)**: TIM17_CH1 PWM 1 kHz, 듀티 1~100 %를 5초에 걸쳐
> 왕복시켜 확인했다. 눈에 보이는 플리커가 없고, **1 %에서도 희미하게 점등**되어
> 전 구간을 쓸 수 있다. 레지스터도 의도대로 들어갔다 —
> `CCMR1=0x68`(PWM1+preload), `CCER=0x03`(출력+active-low), `PSC=47`, `ARR=999`,
> `BDTR=0x8000`(MOE), `GPIOB AFRH` PB9 nibble `= 2`.

### 3.7 키 상태 조회 — `AT+KEY?`

```
AT+KEY?             → +KEYS:0,0,1,0
                      OK
```

디바운스를 거친 현재 상태. `1` = 눌려 있음. 채널 순서는 K1~K4.

> 비요청 통보는 `+KEY:`, 조회 응답은 `+KEYS:`다. 한 줄만 보고도 어느 쪽인지
> 구분할 수 있도록 이름을 다르게 두었다.

### 3.8 전체 상태 — `AT+STATUS?`

```
AT+STATUS?          → +RELAY:1,0,0,0
                      +LED:T,O,W,O
                      +LEDIVL:1000,1000,1000,1000
                      +LEDEN:1
                      +LEDBRI:100
                      +KEYS:0,0,0,0
                      OK
```

ESP32가 재부팅했을 때 MM32를 건드리지 않고 상태를 회수하는 용도다.
각 줄의 형식은 개별 조회 명령의 응답과 완전히 같다 — 파서를 재사용할 수 있다.

### 3.9 버전 — `AT+VER?`

```
AT+VER?             → +VER:x3-switch,0.1.0
                      OK
```

### 3.10 소프트 리셋 — `AT+RST`

```
AT+RST              → OK
                      (송신 버퍼가 빈 뒤 리셋)
                      +READY:x3-switch,0.1.0
```

`x3_uart_board`는 UART 2선만 연결하므로 **ESP32가 MM32를 하드웨어로 리셋할 방법이
없다.** 이 명령이 유일한 원격 복구 수단이다.

## 4. 비요청 통보

| 통보 | 시점 |
|---|---|
| `+READY:x3-switch,<버전>` | 부팅이 끝나고 출력이 초기 상태가 된 직후 1회 |
| `+KEY:<ch>,DOWN` | 키가 눌린 것이 디바운스로 확정된 순간 |
| `+KEY:<ch>,UP` | 키가 떨어진 것이 확정된 순간 |

```
+KEY:3,DOWN
+KEY:3,UP
```

- **MM32는 짧게/길게/더블클릭을 판정하지 않는다.** 생이벤트만 보내고 해석은
  ESP32가 타임스탬프로 한다. 나중에 "길게 누르면 전체 소등" 같은 정책이 생겨도
  MM32 펌웨어는 손대지 않는다.
- 통보는 **명령 응답 사이에 끼어들 수 있다.** ESP32 파서는 줄 단위로 읽으면서
  `+KEY:`를 언제든 받을 수 있어야 한다.

  ```
  ESP32 → AT+RELAY?
  MM32  → +KEY:2,DOWN      ← 이 순간 사용자가 K2를 눌렀다
  MM32  → +RELAY:1,0,0,0
  MM32  → OK
  ```

## 5. 부팅 시퀀스

MM32는 전원 인가 후 수십 ms 안에, ESP32는 1초 가까이 걸려 올라온다.
MM32의 `+READY`는 ESP32가 아직 수신 준비가 안 됐을 때 사라질 수 있다.

```
전원 인가
  │
  ├─ MM32: 클럭 48 MHz → 릴레이 3채널 OFF → LED 4채널 주황 → LED_EN ON
  │        → UART2 열기 → "+READY:x3-switch,0.1.0" 송신
  │
  └─ ESP32: 부팅 (~1 s) → AT+STATUS? 로 상태 확인 → 필요한 상태를 밀어넣음
```

- 초기 상태를 **주황 점등**으로 둔 것은 원본 Tuya 동작과 같아서,
  ESP32가 올라오는 동안에도 벽면이 죽은 것처럼 보이지 않기 때문이다.
- ESP32는 `+READY`를 받으면 **MM32가 리셋되었다**는 뜻으로 해석하고
  자신이 알고 있는 상태를 다시 밀어넣어야 한다.
- `+READY`를 놓쳤을 경우를 대비해 ESP32는 부팅 후 항상 `AT+STATUS?`를 한 번 보낸다.

## 6. 예시 세션

```
                                    +READY:x3-switch,0.1.0     ← MM32 부팅
AT                               →
                                    OK
AT+STATUS?                       →
                                    +RELAY:0,0,0,0
                                    +LED:O,O,O,O
                                    +LEDIVL:1000,1000,1000,1000
                                    +LEDEN:1
                                    +LEDBRI:100
                                    +KEYS:0,0,0,0
                                    OK
                                    +KEY:3,DOWN                ← 사용자가 K3 누름

AT+RELAY=1,1                     →                             ← ESP32 정책: 전등1 ON
```

## 7. ESP32 구현 참고

- 줄 단위로 읽고, `+`로 시작하면 통보이거나 조회 응답, `OK`/`ERROR`는 직전 명령의 종결이다.
- 명령을 보낸 뒤 `OK` 또는 `ERROR`가 올 때까지를 한 트랜잭션으로 본다.
  그 사이에 끼어든 `+KEY:` 줄은 트랜잭션과 무관하게 따로 처리한다.
- 응답 타임아웃은 100 ms면 충분하다 (115200 bps에서 최장 응답인 `AT+STATUS?`가
  6줄 ≈ 70 바이트 ≈ 6 ms).
- 타임아웃이 반복되면 `AT`로 생존을 확인하고, 그래도 응답이 없으면 `AT+RST`를 시도한다.

## 8. 확정 근거

| 결정 | 이유 |
|---|---|
| MM32는 완전 슬레이브 | 상태 소유자를 ESP32 하나로 두어 MQTT와 물리 상태가 어긋나지 않게. 큰방/다른방 차이도 ESP32가 흡수하므로 **MM32 펌웨어는 3대가 동일** |
| 키는 DOWN/UP 생이벤트 | 짧게·길게 판정을 ESP32에 두면 정책이 바뀌어도 MM32를 건드리지 않는다 |
| 클래식 AT 형식 | USB-시리얼 터미널로 사람이 직접 쳐서 디버깅할 수 있다 |
| LED 채널은 W/O/T (소등 없음) | 하이Z 소등이 회로상 불가능함을 실측으로 확인 (§3.3) |
| 점멸 주기는 채널별 | 난방·네트워크 등 서로 다른 상태를 다른 속도로 구분해 표시할 수 있다 |
| `LEDEN`과 `LEDBRI`를 분리 | 상태를 펌웨어 변수로 들고 `CCR1`에 합성해 쓰므로 화면을 껐다 켜도 밝기 설정이 남는다. ESP32가 이전 밝기를 기억할 필요가 없다 |
| 오류는 `ERROR` 하나 | 채널 몇 개짜리 장치에서 오류 번호로 분기할 일이 없다 |
